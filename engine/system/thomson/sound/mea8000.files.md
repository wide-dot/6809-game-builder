# MEA8000 speech files

The players `mea8000.file.read` (polling) and `mea8000.file.read.irq` (interrupt driven)
play speech files in the format Philips defined for the chip (Technical Publication 101,
1983, p. 14) and that Cedic-Nathan used for every Thomson product — the *Synthétiseur de
paroles* cartridge, the phoneme sets, the vocabulary listings of *Parole et Micros*. The
[mea8000](https://github.com/wide-dot/mea8000) encoder produces this format from audio.

## Speech file

| Offset | Size | Content |
|---|---|---|
| 0 | 2 | length of the file, this word included (big endian) |
| 2 | 1 | free byte (Cedic phoneme sets repeat the pitch here) |
| 3 | 1 | starting pitch, Hz / 2 |
| 4 | 4 × n | frames; a frame with AMPL = 0 is silence; the last frame is the AMPL = 0 dummy frame that lets the previous one play to its end |

Frame layout (TP101 fig. 12): byte 1 `BW1 BW2 BW3 BW4` (2 bits each), byte 2 `FM3 (3) FM2 (5)`,
byte 3 `FM1 (5) AMPL (bits 3..1)`, byte 4 `AMPL (bit 0) FD (2) PI (5)`; PI = 16 selects noise.

## Vocabulary image

A table of 16-bit offsets from the start of the image, one per file, ended by `$FFFF`,
followed by the files (TP101 fig. 27). `mea8000.rom.read` plays file number B of the image
at X. The Cedic demonstration cartridge and the phoneme sets are such images.

## Protocol

Both players send STOP (`$1A`), the starting pitch, then every byte of the frames once
REQ (bit 7 of the status) says the chip accepts one. Neither sends a STOP at the end: the
dummy frame has amplitude 0, the chip fades on it and stops by itself 16 ms after it
started, and the polling player waits for that before returning. A STOP sent as the dummy
frame starts — the protocol of TP101 fig. 19 — races the chip's own sample clock: whether
it lands before or after the chip's first sample of the frame depends on the CPU's timing,
and the chip's state (sawtooth phase, filter memory) then differs from one machine to the
next by a sample. Letting the chip stop by itself is deterministic; checked against MAME's
synthesizer sample for sample (2026-09-12), and it is what the Cedic-Nathan demonstration
player does. After the pitch byte REQ stays busy for up to 8 ms, after the fourth byte of
a frame until that frame starts; between the bytes of a frame the chip recovers within
3 µs.

The interrupt player sets ROE (`$1B`) so that the REQ pin drives the IRQ line, sends one byte
per interrupt, and restores `$1A` (REQ pin off) with the final STOP. Like
`mea8000.phonemes.read.irq` it takes the IRQ vector and the 6846 timer interrupt for the
duration of the file.

## Streams over several pages

`mea8000.stream.read` (`mea8000.stream.read.asm`, needs `mea8000.file.read`) plays a
stream longer than a page. The stream is cut into blocks of at most 16 KB at speech-file
boundaries, one block per RAM page, each a file of the disk loaded into the cartridge
window (`$0000-$3FFF` on TO8, pages 5 and up: 0 is video, 1 the program, 4 the loader).
X points at a table of 5 bytes per block: the register byte that maps the page into the
window (`page | map.RAM_OVER_CART`), the block's address in the window, its length; a
zero register byte ends the table. The caller's page is restored. The player maps a page
in a few microseconds between two files, within the chip's own rest, so nothing is heard
of the change. The `mea8000-disks` project cuts a `.mea` stream into blocks and writes the
table and the disk configuration.

## The 2024 variant

`mea8000.digitalized.read` reads the layout the 2024 encoder prototype wrote: a length word,
then groups `pitch + frames`, each group ended by an AMPL = 0 frame that also triggers STOP.
It is not the period format and cannot play Cedic-Nathan data; kept for the files that
still use it (`examples/mplus/src/assets/sounds/mea/harder.mea`).
